# Small Things website: design

**Date:** 2026-09-30

**Owner:** Matt Price (HCS, HISS Hub faculty lead)

**Status:** approved in conversation, 2026-09-30

## Purpose

A public website for *Small Things*, the RIE-funded live-recorded podcast series run by the HISS Research Hub at UTSC, in which the host talks with a HISS faculty member about a single object that opens onto larger cultural and social questions. The site advertises the series, lists every recording, publishes episodes once edited, and carries a combined calendar of three event series: Small Things, the wider HISS Hub programme, and HCS's *Speakers' Corner*.

The site must be editable by colleagues and students through GitHub, with no toolchain beyond a browser for adding an event.

## Decisions taken

| Question | Decision |
| --- | --- |
| Generator | Hugo extended, custom layouts, no third-party theme, no npm |
| Event data | Markdown files in the repo for Small Things and Speakers' Corner; HISS Hub events imported from the Outlook ICS feed at build time |
| Episode schedule | Placeholders marked `status: tbc` until real dates arrive |

## Content model

One Markdown file per event. The folder is the series:

```
content/events/small-things/2026-10-15-episode-1.md
content/events/speakers-corner/2026-10-06-tbc.md
content/events/hiss/                     # generated by import, gitignored
```

Front matter, all events:

- `title` (string, required)
- `date` (RFC 3339 with offset, required): start
- `end` (RFC 3339, optional): end
- `location` (string, optional)
- `status`: one of `confirmed`, `tbc`, `cancelled`; default `confirmed`
- `speakers`: list of strings
- `link`: external URL (registration, more info)
- `series`: set automatically from the folder via cascade; not edited by hand

Small Things episodes add:

- `episode` (integer)
- `object` (string): the thing the episode is about
- `department` (string): guest's department
- `audio` (URL to the published recording, optional)
- `image` (path under `assets/images/`, optional)

Body: the event description in Markdown.

Series descriptions live in `content/events/<series>/_index.md`, each with `title`, `colour` token name, `short` blurb and a body.

Site-wide facts (contact email, hub URL, department URLs, Outlook feed URL) live in `hugo.toml` params and `data/`.

## Import from Outlook

`scripts/import_ics.py` (PEP 723 header, run with `uv run`) downloads the feed URL from `hugo.toml`, parses it with the `icalendar` package, converts Windows timezone names ("Eastern Standard Time") to `America/Toronto`, drops events older than a configurable window (default 400 days), and writes one Markdown file per VEVENT into `content/events/hiss/`, replacing the folder each run. Events whose normalised title matches a repo event's normalised title are skipped, so the same event never appears twice. Recurring events (RRULE) are expanded for the window.

The folder is gitignored. `make import` runs it locally; the site builds correctly when the folder is absent.

## Pages and templates

- **Home** (`layouts/index.html`): full-bleed dark hero for Small Things; next live recording card; latest published episode with an `<audio>` player; next five events across all series; short blurbs linking to the two other series.
- **Small Things** (`layouts/events/list.html` specialised by series): about, how to attend, upcoming recordings, episode archive.
- **Episode / event page** (`layouts/events/single.html`): large episode number and date, object, guest, location, description, audio player if `audio` set, add-to-calendar link (single-event `.ics`).
- **Calendar** (`content/calendar.md` + `layouts/_default/calendar.html`): all series grouped by month, colour chips per series, client-side filter toggles (progressive enhancement; the full list renders without JavaScript), past events collapsed under a toggle, subscribe buttons.
- **Speakers' Corner** and **HISS Hub** series pages: same list layout, own description.
- **About** (`content/about.md`): the Hub, the six departments, funding acknowledgement (RIE, MPF, departments), contact.

## Feeds

Custom Hugo output formats:

- `/calendar.ics`: all events
- `/events/<series>/index.ics`: one per series
- `/events/<series>/<slug>/index.ics`: single event
- `/events/index.json`: machine-readable list

Times are emitted as UTC in the `.ics`, with `X-WR-TIMEZONE:America/Toronto`.

## Look

- Ground: UofT blue `#1e3765`. Series accents: Small Things coral `#ff5c39`; HISS Hub UofT accent blue `#007fa3`; Speakers' Corner a warm yellow `#f5c400`. Text on light `#fbf9f4` paper; dark hero blocks use the blue.
- Type: heavy display sans for numbers and headlines, plain sans for body, monospace for dates, rooms and metadata. Fonts self-hosted as woff2 in `assets/fonts/`.
- Layout: single column up to 72rem, generous margins, no horizontal scroll at 360px. Colour contrast at WCAG AA or better. Series colour is never the only signal; each chip carries the series name.
- SCSS in `assets/scss/`, compiled by Hugo Pipes (libsass in the extended build).

## Collaboration and quality gates

- `README.md`: what the site is, how to add an event in the GitHub web editor in five steps, how to run locally, how the Outlook import works.
- `archetypes/events.md` so `hugo new events/small-things/<slug>.md` produces a filled-in template.
- `scripts/check_events.py`: validates every event file. Fails with a plain-English message listing file, field and problem. Runs in CI before Hugo.
- `Makefile`: `make import`, `make check`, `make build`, `make serve`, `make test`.
- Tests (`pytest`, run via `uv run`): timezone mapping, dedup by title, RRULE expansion, validator accepts good files and rejects each kind of bad file. `tests/test_build.py` runs `hugo` into a temp dir and asserts the expected pages and feeds exist and that `calendar.ics` parses.
- `.github/workflows/deploy.yml`: on push to `main` build and deploy to Pages; on pull request build only; daily cron 10:00 UTC (06:00 Toronto) build and deploy. Uses `peaceiris/actions-hugo` or the official `actions/configure-pages` pattern. `baseURL` comes from a single value in the workflow.
